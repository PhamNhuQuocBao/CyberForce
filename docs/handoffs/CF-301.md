# CF-301 — Docker lab spawner backend

## Phạm vi đã duyệt

Người dùng duyệt Go Docker SDK, API spawn/stop ở backend, Docker socket chỉ cấp cho daemon, mạng lab cô lập trong `100.64.0.0/10`, dùng bảng `lab_instances` hiện có. UI terminal và reaper thuộc task sau. Không đổi schema.

## Triển khai

- Go daemon dùng Docker Engine SDK qua Unix socket. Mỗi instance có network bridge `internal` riêng `/29` và IP trong `100.64.0.0/10`; không publish port. Image chỉ nhận dạng `cyberforce/<name>:<tag>` và phải có sẵn trên Docker host.
- Container: `NanoCPUs=2000000000`, `Memory=MemorySwap=2147483648`, `PidsLimit=512`, `CapDrop=["ALL"]`, `no-new-privileges`, không bật privileged hoặc bind mount. Spawn dọn container/network nếu thất bại; stop idempotent và chỉ xóa tài nguyên mang nhãn instance tương ứng.
- Daemon có API nội bộ `POST /v1/instances`, `DELETE /v1/instances/:id` với bearer token; không publish cổng ra host. Entrypoint lấy GID Docker socket rồi chạy daemon bằng user `app`.
- API Core có `POST /api/v1/rooms/:slug/spawn` và `POST /api/v1/rooms/:slug/stop`. Spawn dùng kiểm tra truy cập CF-202 (đăng nhập, xuất bản, trả phí, prerequisite), chặn quá một máy active mỗi user bằng khóa Redis, lưu `LabInstance` với salt động và hạn 60 phút. Stop chỉ cho chủ phiên, kể cả khi phòng đổi trạng thái xuất bản. Response không lộ image, container ID hoặc salt.
- `ORCHESTRATOR_TOKEN` phải đổi trước môi trường production. Giá trị mặc định chỉ dành cho local; API từ chối spawn trong production nếu vẫn dùng giá trị này.

## Kiểm chứng

- Go unit tests kiểm tra chính sách tài nguyên/network và xác thực API nội bộ; API Core full suite 107 tests trên schema riêng `cf301_test_20261013`, Redis DB13; typecheck/lint/build pass.
- Compose daemon chạy healthy trong project riêng `cf301-smoke`. Với image local `cyberforce/cf301-smoke:test`, POST spawn trả IP `100.103.193.98` trong `0.174s`; `docker inspect` xác nhận 2 vCPU, RAM 2 GB, tổng RAM + swap 2 GB, 512 PID, `CapDrop=ALL`, privileged=false; network `internal` trong `100.64.0.0/10`. Container không truy cập được `1.1.1.1`. DELETE trả 204 và xóa container/network.
- Lệnh `docker compose up -d --build --wait` trên project/cổng/volume riêng `cf301-full` exit 0: PostgreSQL, Redis, MinIO, guacd, Traefik, orchestrator, API và web đều healthy; `db-init` exit 0. Project/volume thử nghiệm đã dọn sau kiểm tra.
- Public API E2E với schema `cf301_test_20261013` và daemon Docker thật: authenticated `POST /rooms/:slug/spawn` trả 201, `docker inspect` thấy container đang chạy, DB ghi IP `100.110.109.194`/status `running`; `POST /rooms/:slug/stop` trả 200, DB chuyển `terminated`, không còn container lab. Script kiểm thử exit 0 và tài nguyên tạm đã dọn.

## Giới hạn và bước sau

- SLA dưới 3 giây mới kiểm tra với image có sẵn, một phiên local; chưa benchmark dưới tải hoặc tính thời gian pull image.
- CF-302 cần reaper 30 giây, gia hạn tối đa ba lần, xử lý phiên `provisioning` mồ côi sau crash và hết hạn. Trước CF-302, API stop thủ công là cách dọn phiên và bản ghi `running` hết hạn vẫn chặn spawn mới.
- Dynamic flag injection, AttackBox, VPN routing và terminal/Guacamole chưa nối; `dynamicSalt` mới được lưu cho phiên. Docker `internal` chặn egress Internet nhưng host gateway vẫn là bề mặt cần kiểm soát thêm ở CF-402.
